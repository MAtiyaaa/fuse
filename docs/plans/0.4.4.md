# Fuse 0.4.4 - The Overdrive Update: the plan

This is the working plan for 0.4.4. Each pillar is split into pieces that can each be merged on
their own, with the modules they touch, the tests that prove them and the order they go in. A
piece is done when its tests pass in `./gradlew allTests`, CI is green, its docs say what the code
does, and every claim is measured.

Written after reading ARCHITECTURE.md, DESIGN_SYSTEM.md, CONTRIBUTING.md, INTEGRATIONS.md,
docs/sync.md, docs/emulator-contracts.md and ROADMAP.md in full, and the code each pillar touches.

## Ground rules (every pillar)

- **Sources.** Every fact about an emulator, Steam, RomM or another service comes from that
  project's own source, specification or documentation, cited in the KDoc beside the code (file and
  function, as the catalogs do). Other launchers' and clients' code is never read, ported or
  paraphrased.
- **Boundaries.** Shared code in `commonMain`; anything the system owns behind `FuseServices` and
  `PlatformUi`. `core:launch` stays pure (data and plans, never I/O), `core:library` never writes,
  `core:integrations` never stores, and the data layer owns storage.
- **Emulator files.** Changed only when the person asks; atomically; a backup first; recorded in
  `OwnedChangesRepository`; undoable; never while the emulator runs; the file's own formatting
  kept; parsed before and after, with the old file put back when the new one doesn't parse.
- **Secrets.** New ones go in `SecretStore` behind `Secret`, through `redact()`, never logged,
  exported, backed up or put in a URL that is kept, and travel only sealed through Fuse One.
  Third-party passwords (RPCN, a RomM sign-in used to make a token) are used once and never kept.
- **Honest.** Nothing touches the network until it is set up. Unknown is said as Unknown. No
  blocking work on the interface thread.
- **Interface.** Lucide icons only, design tokens, no em dashes, no emojis, British spelling, Title
  Case on buttons and titles. Controller, touch, mouse and keyboard; every theme, light and dark;
  all 23 audit sizes.
- **Platforms.** Every platform where it can work, and where it can't, the screen says why.
- **Tests** are written with the code, never after.

## Order

Pillars that others lean on come first. Each line is merged and green before the next starts.

1. Pillar 11 (Every screen finished) pieces that are small and self-contained, alongside the rest.
2. Pillar 1 (Fuse in Game Mode): Fast Start is what Steam entries, Ports and Decky all start.
3. Pillar 2 (Fuse Tune): the settings data Add-ons and Play Together reuse.
4. Pillar 3 (RomM saves), then Pillar 4 (RomM both ways).
5. Pillar 5 (Emulator Store), then Pillar 6 (Add-ons).
6. Pillar 7 (Play Together).
7. Pillar 9 (Achievements everywhere).
8. Pillar 8 (Fuse Ports).
9. Pillar 10 (Proof) grows with every pillar; its CI jobs land as soon as they have something to run.

## Product choices

Asked on 18 October 2026; the first four were answered, the rest take the recommendation until
said otherwise.

1. **Version code.** 0.4.3 ships as it is (code 76) and 0.4.4 is code 77, on its own branch and pull
   request. *Decided.*
2. **Steam entries by default.** Fast Start (saves kept in step, time counted, profiles), with Direct
   as a choice per game or for all. *Decided.*
3. **RomM at home.** Offered only on a computer with Docker or Podman already installed; Fuse writes
   the Compose file in its own folder and never installs Docker or Podman. *Decided.*
4. **Fuse Ports index.** Signed in CI with an Ed25519 key kept as a repository secret; Fuse ships
   only the public key, and until the secret exists no port shows as verified. *Decided.*
5. **Automatic Steam add and remove.** Off by default everywhere, offered once after the first
   manual add. *Recommended.*
6. **Save owner precedence.** Fuse One first, then RomM, then Syncthing. *Recommended.*
7. **Update channels.** Beta is GitHub pre-releases; Nightly is one rolling `nightly` pre-release
   replaced by the nightly job; Stable stays the default. *Recommended.*
8. **Nexus Mods.** The person's own personal API key only; no Fuse application key. *Recommended.*
