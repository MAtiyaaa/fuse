## Causes established in code

| Cause | Consequence | Change |
| --- | --- | --- |
| Desktop static content always took the CPU bitmap path, including accelerated renderers | Transforms enlarged already-rasterized content and regeneration repainted large surfaces | Retain drawing commands in GPU graphics layers; bound software raster caches and redraw oversized content directly |
| Frame history pooled samples from independently paced clocks | A 60 Hz display could influence pressure estimates for a 120 Hz display | Keep history, moving state and pacing decisions per clock; preserve time-based kernels and retarget continuity |
| Decorative motion held after input without sustained frame-pressure evidence | Healthy input could arbitrarily freeze ambient motion | Pressure-driven optional-work reduction; clear moving state when its driver finishes |
| Artwork sizing only resolved one content-scale path and Jellyfin URLs used fixed widths | Large cards could enlarge handheld-sized requests; resize requests could churn | Physical-pixel buckets with focus headroom, budget limits, bucket cache keys and retained previous painters |
| Focused siblings kept ordinary paint order and shelves lacked overflow space | Enlarged cards could draw beneath adjacent cards | Reusable Tile focus z-order and Store shelf overflow spacing |
| A fresh artwork model was marked shown before consulting shown history | First network loads could bypass their intended fade | Read history before registering first display |
| Profile hydration could write an old profile's settings under the new profile; sync stamped snapshots at transmission time | A late startup/sync writer could appear newer and undo a legitimate choice | Durable per-setting HLC/origin/value records, matching value/revision exports and explicit hydration ownership |
| Untouched inherited profile settings were not seeded durably | Leaving a profile and returning could lose inherited choices | Seed inherited settings when establishing profile ownership |
| Device registry and remembered libraries were treated as separate topology, with unsafe self/list-size assumptions | Send targets could claim no household devices despite visible remote libraries | Reconcile registry, remembered library and seen evidence; test explicit non-self existence |
| Weak title aliases joined records despite conflicting serials; already-bound strong aliases could fail to converge | False merges and contradictory copies or duplicate knowledge | Strong-key matching, serial/hash conflict guards, compatible strong-group joins and cached alias repair |
| Scrape demand lacked shared queued priority and cancelled owners cancelled followers | Visible requests could wait behind bulk work or lose a surviving consumer | Bounded provider scheduler, shared priority promotion, coalescing and follower recovery |
| Provider spelling differed between legacy and current claims | A trusted identity could be missed or conflict handling bypassed | Canonicalize known provider names while preserving unknown provider strings |
| PS4/PS5 title roots lacked an enforced resource ownership boundary | Internal resources could become titles | Recognize structured title roots and contain runtime/resources within them |
| Legacy Switch child rows with user state survived untouched-entry cleanup | Old updates/DLC remained standalone games | Durable child-to-owner archival with selective intent/history reconciliation |
| Scan folder timestamps alone could retain obsolete interpretation | Existing libraries might never run new semantic rules | Persist scanner-rules version and perform necessary one-time reevaluation |
| Save replacement preceded durable imported-revision commit | A failed commit could leave files changed without Sync history | Staging, safety history, rollback copies, durable commit callback and recovery journal |
| Refresh mode policy was tied to performance quality | Balanced could request approximately 60 Hz on a 120 Hz panel | Native-resolution maximum by default, independent manual cap, per-window requests and cadence diagnostics |
| Standby state belonged to one AppState/window | Companion or newly attached displays could remain bright | Shared display-session standby plus consumed wake/held input |
| Developer onboarding reused the production environment with write guards | Personal data could be read or side effects escape guards | Standalone in-memory store, fake platform/services and independent input/coroutine lifecycle |
| Shortcut matching used broad Fuse-like names and binary parsing accepted incomplete input | Repair could touch unrelated entries or rewrite malformed data | Positive program matching, strict parse, backups and atomic replacement |

The L1/R1 ghost has **not** been reproduced or causally established. HUD alpha/mask changes are
implementation improvements, not evidence that this artifact is fixed. The previous short noise
period is a plausible contributor to TV squares; the new coprime pixel fields require physical

## State and migration semantics

Settings keep their original durable revisions when transmitted. Newer remote choices propagate;
older remote choices cannot win just because they arrive later. Device-local display caps remain
separate from profile theme choices. Legacy unversioned settings are seeded rather than repeatedly
restamped at every sync.

Schema 4 to 5 adds `game_absorption`. Retired Switch children retain their original custom titles,
provider metadata and artwork for recovery. Favourite/pin intent, collection membership and play
history are selectively reconciled. Child hidden/custom-title/provider/artwork values do not blindly
replace the base title. Inactive profile snapshots normalize proven child ownership. No game
packages are reorganized or emulator NAND contents guessed.

Unambiguous legacy household identity groups keep their metadata and histories when canonicalized.
Conflicting serial groups split future identities; ambiguous pooled historical data stays stored
under its old identity instead of guessing ownership. Such history may require explicit recovery.

Save import copies from files, directories or bounded ZIP extraction and builds an editable preview
using existing adapters/formats. Unknown or incompatible data stays unmatched. Existing saves are
captured before replacement. Imported revisions use the existing outbox/history and additive
Imported provenance; offline imports queue normally. A partial batch reports successes and individual
failures and retries only failed selections. The journal supports interrupted replacement recovery;
late independent emulator edits block automatic recovery and retain safety copies. This is not a
claim of filesystem power-loss durability or arbitrary save-state conversion.

## Material modules

`core/model`: refresh/artwork sizing and provider claims.
`core/data`: causal settings, provider claims, semantic ownership migration and profile reconciliation.
`core/library`: structured scanning, semantic cache version, Steam identity and strict shortcut formats.
`core/integrations`: provider scheduling, direct IDs, cooldowns and [GameTDB](../providers/convergence-artwork.md).
`core/sync`: identity/topology, monotonic host clock, safe importer, recovery and outbox integration.
`ui/fuseline`: narrowly scoped per-clock pressure/pacing correction; existing solver architecture retained.
`ui/designsystem`: retained static layers, focus order, artwork buckets, noise and optional tracing.
`ui/shell`: importer preview, profile presentation, fake onboarding, household matching and UI scenarios.
`app/android`: native refresh mode requests/diagnostics, display session and bounded save staging.
`app/desktop`: active renderer tracing, save picker and Steam lifecycle/repair.

`5.db`; foreign-key check returned no violations. Repository whitespace check passed at integration
review. Kotlin compilation and regression suites are currently pending the coordinated build.

interruption, refresh selection, independent pacing, standby wake and fake onboarding isolation.
Existing Fuseline equivalence and engine benchmarks remain available and must pass.

No before/after performance measurements have yet been collected. No improvement percentage,
input latency or device frame rate is asserted. `--trace-ui` measures root composition, layout,
CPU draw/recording/raster costs and input-to-next-root-draw, with bounded p50/p95/p99 samples.
This is a lower-bound diagnostic, **not** input-to-presentation. It does not measure GPU submissions,
texture uploads or compositor delivery. Its frame-clock observer changes idle behavior, so compare
identically instrumented runs.

The product `desktopPerf` task includes actual Skia drawing/readback and JFR, separate from engine
math timing. Virtual viewport/cadence matrices are deterministic software workloads, not physical
Steam Deck, compositor, vsync or multi-display tests. Background-scrape performance coverage remains
an explicit fixture gap.

## Physical acceptance still required

No Steam Deck, AYN Thor, Android display, TV, multi-device household or authenticated external
service has been physically tested in this workspace. No accelerated Vulkan/OpenGL, SteamOS Game
Mode, KDE/GNOME Wayland/X11 presentation, Windows or macOS hardware coverage is claimed.

Outstanding release acceptance includes input-to-presented-frame measurements and renderer/cache
profiling, L1/R1 artifact reproduction, TV grain/banding and sharpness at viewing distance, live
widget appearance, Steam clean shutdown/restart/onboarding resume on real installations, refresh
requests versus active/cadence on dual-screen hardware, and all multi-device service/save conflict
scenarios. Steam remembered users and manifest LastOwner are provenance, not authentication or
licence proof; Fuse does not share tokens/passwords or log users into Steam. Additional provider
asset sharing/persistent result caching and a full structural catalog audit require further work.

Do not publish this release as complete while these acceptance items remain unverified.
