# Platform ownership audit for 0.4.1

This is a code and format audit, not an emulator compatibility certification. The inventory below covers every one of the 157 entries in `CatalogPlatforms.kt`. Catalog inclusion and an accepted extension do not prove that Fuse can inspect a format's internals or that the selected emulator can launch it. The Switch classification and organization decisions remain the existing source of truth; this audit does not repeat that investigation.

## Ownership rules

| Rule | One game and launch target | Owned auxiliary content | Updates, firmware, saves and identity |
| --- | --- | --- | --- |
| Cartridge | One ROM or emulator-supported ROM archive; launch the file. Organizational directories remain collections. | Attached RomM categories, patches and metadata stay with the title; an arbitrary ZIP is not interpreted as a save or installed title. | BIOS filenames come from `KnownBios` where specified. Save/state extensions and media folders are excluded. No universal update/DLC layout. ROM header/checksum/database evidence is preferable to names; Fuse does not currently decode every cartridge header. |
| Media | A launchable disc/tape/disk image, or an M3U disc set; launch the sheet, playlist or first disc. | CUE/GDI referenced tracks, CCD IMG/SUB and MDS MDF belong to their descriptor, including references into subfolders. Disc markers group sibling discs. | Firmware belongs outside titles. Patch/manual/cheat files attach within a recognized game folder. Saves belong to emulator adapters, not the disc set. PS1/PS2 uncompressed images have a serial reader and PS2 executable CRC; compressed images are not decoded by it. Other media identities require emulator/provider/header evidence rather than filename equality. |
| Arcade | A ROM set is identified by the emulator's machine/shortname and its database, not a friendly filename. Launch its supported set archive or entry. | ROM chips, parent/clone dependencies and CHDs are parts of the machine set. They must not be independently merged by friendly-title resemblance. | BIOS/device sets and CHD delta parents are dependencies. Known BIOS sets are filtered, but the catalog is not a complete MAME machine database. A same-shortname CHD directory beside a ZIP is a remaining scanner gap, described below. |
| PS3 | Disc folder with PS3_DISC.SFB/PS3_GAME, HDD folder with USRDIR and PARAM.SFO/EBOOT.BIN, supported image/package or installed-title descriptor. | Recognition establishes a descendant ownership boundary; do not recurse through runtime resources as games. Existing launcher adapters resolve folder boot behavior. | Package metadata classifies update/DLC and title ID. RPCS3 installed content reader separates game storage/licences from saves/firmware/cache; installed updates can overlay game storage. TITLE_ID is stronger than names. |
| Vita | sce_sys/param.sfo folder, VPK/PKG or title-bearing ZIP, installed-title descriptor. | sce_sys and runtime descendants belong to the title; local icon/background artwork can be reused. | Existing Vita3K reader distinguishes ux0/app, patch, addcont and licences. Header title ID/category wins; small ZIPs without a recognized title are rejected. Large unreadable ZIP fallback is a compatibility heuristic, not proven identity. |
| Modern PS | PS4 sce_sys/param.sfo or PS5 param.json; eboot.bin establishes an incomplete title boundary. PS5 uses eboot.bin when present. | All title descendants, including arbitrary materials/resources, are owned by the recognized root. | PS4 CATEGORY gp/ac classifies updates/DLC; title IDs and existing update folding apply. Firmware, emulator data and saves stay outside title inventory. PS5 incomplete metadata remains a limitation for distinguishing base/update/DLC. |
| PSP | Supported disc/PBP/homebrew file, or PSP_GAME extracted title folder. | Extracted runtime files belong to the folder; descriptor/disc rules apply to images. | Save hierarchy is PPSSPP-owned, not part of the game scan. Serial/header evidence is desirable; no generic standalone PRX-to-game identity proof. |
| 3DS | Cartridge/container, executable/homebrew or installed-title descriptor. | CIA update/DLC content is matched by normalized base title ID; do not interpret installed content fragments as separate titles. | Existing Cia reader interprets CIA/TMD and cartridge IDs; InstalledContentReader reads Azahar title storage with TMD validation and boot .app. NAND/firmware/cache/save storage remains separate. Encrypted/unknown containers cannot be confidently identified by an extension alone. |
| Wii U | WUA/WUD/WUX or extracted code/content/meta title; extracted launch target is code/*.rpx. | Once the title root is recognized, code, content and meta belong to that title. | Cemu installation is a title-ID hierarchy and installer operation, not an arbitrary update directory. Scanner currently lacks metadata-based folding of extracted installed update/DLC groups; see remaining gaps. Saves and shader cache stay outside title roots. |
| Switch | Existing Switch inventory/consolidation rules and package launch targets. | Base, duplicates, update and DLC attach using existing conclusions; no new filesystem reorganization in this audit. | Existing semantic-version invalidation and legacy absorption migration apply. Emulator-specific install/content behavior remains existing implementation. Household identity must survive path changes. |
| Xbox | XISO/ISO image, or an extracted default.xbe folder ownership boundary. | Extracted resources belong to the title root. The boundary does not prove emulator launch support. | xemu requires a supported disc image and does not directly launch XBE. BIOS/EEPROM/HDD, saves and emulator cache are emulator assets. Fuse does not manufacture an image or claim arbitrary extracted folder launch compatibility. |
| Xbox 360 | Supported image/container, extracted default.xex folder or extensionless installed title under explicit folder policy. | Recognized extracted title descendants are owned by the title; launch default.xex. | STFS/XBLA metadata, title IDs and base/update/DLC categories need stronger parsing than extensions. Folder-as-game fallback preserves unknown titles but is not metadata classification. No content movement is performed. |
| PC folder | Explicit per-title folder/descriptor, or unambiguous program/shortcut; launch selected descriptor/program, otherwise preserve folder choice for correction. | Runtime resources, engine assets and helper executables stay under the chosen title. Multiple possible launchers require correction rather than a guessed executable. | Installers/helpers are not preferred launch programs. Local account ownership and Steam app ID evidence are separate from file path. Mods, engine packs and expansion archives require engine-specific knowledge; all WAD/PAK files are not intrinsically separate games. Saves are adapter-owned. |
| Program | One supported executable/cart/story file or installed application identity. | Runtime data can require a folder; an extension cannot establish dependency ownership. | No general update/DLC convention. Installed app/package identity or format signature is stronger than a display name. BIOS/system assets are not titles. PNG cart formats require signature awareness; arbitrary PNG acceptance is a remaining gap. |

All rules retain the existing explicit folder policies. `FILE` opts into walking files and `FOLDER_BROWSER` opts into browsing; automatic title boundaries do not override these choices. Organizational folder names only help decide navigation grouping, never prove title identity. The new direct-root fix applies marker-based recognition to an extracted title that is itself the configured platform folder. It excludes mixed PC roots, where one executable cannot prove ownership of adjacent directories.

## Catalog inventory

Each row names the applicable ownership rule above. `Cartridge / Media` means the system supports both file-native ROMs and disk/tape/disc media; the actual descriptor/signature must decide, not the platform name alone. `Program / PC folder` means installed runtime data may be folder-owned while a configured launcher remains the launch target.

## Remaining structural gaps

- MAME's documented shortname directory can contain CHDs belonging to a sibling ROM-set ZIP. The current generic scanner can list that directory as another game. Safe reconciliation needs machine-set evidence, preserving parent/clone dependencies and disk roles. Arbitrary matching friendly titles is insufficient. The finite BIOS-name list also cannot replace MAME's machine database.
- Cemu installed groups `00050000`, `0005000e`, `0005000c` represent base/update/DLC, with title identity described by metadata. Current scanner storage traversal recognizes eight-digit groups and extracted RPX boundaries but does not parse that metadata to fold all installed content. It can preserve update/DLC as separate entries. A dedicated title-ID reader and upgrade reconciliation are still required.
- Xbox 360 STFS/XBLA packages and their title-update hierarchies are not fully decoded. Preserving a folder entry is intentional but cannot distinguish every game from emulator content.
- PICO-8 and TIC-80 accept PNG in the catalog. A PNG extension alone cannot prove a playable cart; a bounded format-signature check remains required. This audit does not silently delete pre-existing PNG entries.
- Doom/Quake engine data packs, shared assets and expansions require engine manifests/launch descriptors. Catalog extension lists cannot classify every WAD/PAK as a separate title or safely combine unrelated mods.
- Many older-computer media formats, generic archives and newer-system encrypted containers retain extension-based fallback. Unknown content is preserved rather than destructively classified or assigned provider identity. Full archive/header semantics across all 157 platforms are not implemented by this change.

These gaps mean the catalog-wide structural acceptance requirement is not fully satisfied. They are recorded explicitly so the release report cannot mistake catalog coverage for complete format understanding.

## Regression fixtures and source evidence

`FolderInterpreterTest` exercises direct extracted roots across PS3, PSP, Wii U, Xbox and Xbox 360, title metadata for a direct Vita root, explicit FILE policy, and a mixed PC root whose adjacent games must remain visible. These synthetic filesystem fixtures verify scan ownership and launch-target preservation, not physical emulator launch.

The broader existing suites cover playlists/tracks, PS3/Vita packages, 3DS content, PS4/PS5 boundaries, Switch consolidation and semantic cache invalidation. Test execution is recorded by the integration owner in the release audit; no emulator or hardware was launched by this audit.

Primary format references inspected on 2026-10-08:

- [RPCS3 boot implementation](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Emu/System.cpp), disc/HDD entry points and title metadata.
- [Cemu extracted formats](https://wiki.cemu.info/wiki/Serfrosts_Cemu_Setup_Guide), code/content/meta and RPX launch layout; [Cemu installation guide](https://wiki.cemu.info/wiki/Installation_guide), metadata-based installation.
- [Cemu title checksums](https://github.com/cemu-project/title-checksums/blob/master/0005000e10102000_v32.json), a concrete update title with code/content/meta rather than a filename exception.
- [xemu FAQ](https://xemu.app/docs/faq/), direct XBE is not supported; [disc images](https://xemu.app/docs/disc-images/), actual accepted launch format.
- [MAME asset search](https://docs.mamedev.org/usingmame/assetsearch.html), shortname directories, parents, BIOS and CHDs; [ROM sets](https://docs.mamedev.org/usingmame/aboutromsets.html), component and delta relationships.
- [ScummVM command line](https://docs.scummvm.org/en/v2026.1.0/advanced_topics/command_line.html), game ID plus game-data path; [Libretro ScummVM](https://docs.libretro.com/library/scummvm/), launcher hooks and detection.

The remaining inventory classifications are an audit of Fuse's catalog, scan rules, installed-content readers, disc grouping and launch policy. They are not claims that external formats absent from those readers were validated.
